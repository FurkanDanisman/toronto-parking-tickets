A `.qmd` file is a Quarto document, and Quarto still produces the PDF through LaTeX. We're using it instead of a plain `.tex` file because the task requires it: it says to prepare the PDF "using Quarto `paper/paper.qmd`". So submitting a `.tex` file would miss that requirement.

**What a `.qmd` is:** a text file that mixes three things:
- **Your writing**, in Markdown, which is simpler than LaTeX: `# Introduction` instead of `\section{Introduction}`, and `**bold**` instead of `\textbf{bold}`.
- **R code chunks** that make the figures, tables and numbers. They run when the paper is built, but the code itself never appears in the PDF, which is another requirement.
- **Citations**, like `[@shoup2005]`, which are pulled from `references.bib`.

**What happens when you render:** Quarto runs the R code, turns everything into a `.tex` file, and compiles it with `pdflatex`, the same LaTeX installation on your Mac. The `.tex` file is just a temporary step that Quarto deletes afterwards. If you want to see it, add `keep-tex: true` under `pdf:` in the header.

**Why it's better here than writing the `.tex` yourself:**
- **Figures and numbers are always current.** They're built from the data every time you render. In a `.tex` file you'd paste in PNGs and type numbers by hand, which go stale whenever the data changes. That matters because the task requires the workflow to be "entirely reproducible".
- **LaTeX still works inside it.** You can use equations (`$y_{it} = ...$`) and commands like `\newpage` directly; the draft already does.

**How to render in VS Code:** open `paper/paper.qmd` and click the **Render** button at the top right (the Quarto extension adds it), or press `Cmd+Shift+K`. The PDF updates next to it. From the terminal, it's `quarto render paper/paper.qmd`.

```markdown
@fig-did-groups shows the two groups moving together in the year before construction started, and the first estimate in @fig-did-estimates, for 7 to 12 months before the start, is not statistically different from zero. Both support the parallel trends assumption. With this support, we estimate the effect of construction with the regression

$$
y_{it} = \alpha_i + \gamma_{s(i),t} + \beta D_{it} + \varepsilon_{it}.
$$

Each construction block and its five matched control blocks form a group, and each group is followed from 12 months before to 24 months after its construction started. In the equation:

- $y_{it}$ is the number of parking tickets on block $i$ in month $t$.
- $\alpha_i$ is the usual number of tickets on block $i$. It lets busy and quiet blocks start at different levels, so each block is compared only with itself.
- $\gamma_{s(i),t}$ is the average for the group $s(i)$ that block $i$ belongs to, in calendar month $t$. It captures anything a construction block shares with its own control blocks in that month, such as a citywide enforcement campaign, a holiday or a snowy February.
- $D_{it}$ equals 1 for a construction block in the months after its construction started, and 0 otherwise, including for every control block.
- $\beta$ is the effect of construction: the number of extra tickets per month on a construction block after construction started, beyond the change seen on its control blocks over the same months.
- $\varepsilon_{it}$ is the part of the ticket count the model does not explain.

The five control blocks in each group are weighted equally so that together they count as much as their construction block. To see how the effect develops over time, @fig-did-estimates replaces $D_{it}$ with a separate indicator for each six-month period before and after construction started, measured relative to the six months just before the start.

Each estimate comes with a 95 percent confidence interval: the range of effects consistent with the data. If the study were repeated many times, 95 percent of intervals built this way would contain the true effect. The p-value is the probability of seeing an effect at least as large as the one estimated if construction in fact had no effect; a p-value below 0.05 is conventionally treated as statistically significant. Because ticket counts on the same block are related from month to month, the intervals and p-values allow for this correlation within each block.
```

It describes exactly what `06-construction_analysis.R` estimates:
- **Model:** a regression with block and group-by-month fixed effects, with the five control blocks weighted equally.
- **Uncertainty:** the intervals and p-values allow for correlation within each block.
- **Figure 3's version:** the same model with six-month period indicators.

On the parallel trends wording: it says the evidence **supports** the assumption, not that the assumption is **satisfied**. The assumption is about what would have happened without construction, which can't be observed, so it can be supported but never proven.
